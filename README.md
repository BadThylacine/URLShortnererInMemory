# URL Shortener

A small URL shortener built as a home assignment. It provides a web form, a REST API, and HTTP redirects when a short link is visited.

---

## Functional Requirements

- Users can submit a long URL and receive a shortened version.
- Users can visit a short URL and be redirected to the original.

Optional (not yet implemented):
- Custom aliases (e.g. `localhost:8080/my-alias`)
- Expiration dates for short URLs
- User authentication and resource management

## Non-Functional Requirements

- Each short code maps to exactly one long URL (uniqueness guaranteed).
- Redirects complete with minimal delay (target: <200ms).

Optional (requires a persistent database):
- 99.99% availability (CAP Theorem: availability over consistency)

---

## Prerequisites

- Java 21+
- Maven 3.8+

## Running the Application

```bash
mvn spring-boot:run
```

Open [http://localhost:8080](http://localhost:8080), enter a URL (e.g. `https://example.com/page`), and submit. The shortened link is displayed on the page. Click it, or open it in a new tab, to be redirected.

---

## API

### Shorten a URL

```http
POST /api/shorten
Content-Type: application/json

{ "url": "https://example.com/page" }
```

**Response 200:**
```json
{ "shortUrl": "http://localhost:8080/aB3x" }
```

**Response 400** — returned when the URL is missing, malformed, or uses a non-http/https scheme:
```json
{ "message": "Invalid input" }
```

### Redirect

```http
GET /{code}
```

Returns `302 Found` with a `Location` header pointing to the original URL.
Returns `404` if the code is unknown, invalid, or does not match the 4-character format.

## Configuration

`src/main/resources/application.properties`:

| Property | Default | Description |
|----------|---------|-------------|
| `server.port` | `8080` | HTTP port |
| `app.base-url` | `http://localhost:8080` | Prefix used when building short URLs |

When deploying behind a proxy or on a public host, set `app.base-url` to the public address (e.g. `https://short.example.com`).

## Technical Decisions

**Spring Boot** — Embedded server, static file serving, REST, and dependency injection in one stack. Fast to set up, easy to extend.

**Counter-based code generation** — Short codes are generated by encoding a monotonically incrementing `AtomicLong` counter into a Base-66 alphabet (a–z, A–Z, 0–9, `-._~`). This guarantees uniqueness without collision retries. With 4-character codes the system supports up to 66⁴ ≈ 18.9 million entries. Increasing `CODE_LENGTH` to 6 raises that to ~82 billion.

**RFC 3986 safe character set** — The alphabet uses only unreserved characters as defined by RFC 3986 (`A–Z a–z 0–9 - . _ ~`). These carry no special syntactic meaning in any part of a URL and never require percent-encoding.

**http/https-only input validation** — `isValidUrl` rejects any URL whose scheme is not `http` or `https`. This prevents abuse via `javascript:`, `file:`, `data:`, and similar schemes that have no legitimate use in a link shortener and could introduce security risks.

**`ConcurrentHashMap` for thread safety** — The in-memory store uses `ConcurrentHashMap` rather than `HashMap`. Combined with the `AtomicLong` counter, all read and write operations are thread-safe without coarse-grained locking.

**In-memory storage** — Data is lost on restart. This is acceptable for the current scope. The `HashMap` in `UrlShortenerService` can be replaced with a database-backed repository without any changes to the API or UI.

**Separate redirect controller** — `RedirectController` handles `GET /{code}` redirects; `UrlShortenerController` handles JSON endpoints under `/api`. This keeps routing concerns separate.

**Code validation on redirect** — Only exact 4-character path segments composed entirely of alphabet characters are treated as short codes. Paths like `/index.html` or `/favicon.ico` are not mistaken for codes and fall through normally.
